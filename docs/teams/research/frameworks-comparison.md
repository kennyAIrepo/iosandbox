# How AR-effect and game add-ons integrate into video calls today (verified 2026-09-18)

Scope: the platforms hopeOS could ride on (Teams first), the Web AR SDKs that show how a browser app injects effects into a call, "own-client" SDKs that expose raw media, and locally-tracked avatar products. Every cell cites the primary source I re-fetched on 2026-09-18. Where a source could not be fetched or does not state a fact, the cell says so.

Legend for "gating": *store* = marketplace review before public listing; *admin* = tenant/workspace admin can block or must allow; *beta* = the vendor marks the API preview/beta; *host* = only the meeting host can start it.

## Three cross-cutting facts that decide our architecture

1. **No meeting add-on surface gives a third party pixels of other people's video.** Zoom Layers composes participants as opaque cutout layers with no frame API; Meet add-ons and Teams stage apps get no media; Teams video-effect apps get only your own outgoing frames. Remote frames exist only when you own the client (ACS `getMediaStream()`, Zoom Video SDK, our own WebRTC twin) or in Google's Developer-Preview Meet Media API, which is receive-only and requires every participant to be enrolled. The "Teams twin" sandbox is therefore the only place cross-tile hand tracking on remote frames can run today.

2. **"Draw over everyone" exists only as host-controlled scene composition, and it is shrinking.** Zoom Immersive mode (host-only, one context) is the one live API. Teams Together mode was retired 2026-06-30, Mesh in Teams 2025-12-01, Workrooms 2026-02-16, and the Games for Work pilot was pulled 2024-05-24. What persists on every platform is per-user effects (video filters, camera mode, avatars) and iframe apps (stage, main stage, activities).

3. **Every in-browser AR SDK converges on one output contract:** render to a canvas, `canvas.captureStream()`, hand the track to the call (`replaceTrack`, ACS `LocalVideoStream`/`setMediaStream`, Banuba `MediaStreamCapture`, Snap `output.capture`, Zoom Video SDK `VideoProcessor` with an `OffscreenCanvas`). hopeOS already renders three.js to a canvas, so "hopeOS as a Teams video effect" is a container question (TeamsJS frame callback, >= 22 fps at 720p, NV12, both handlers) rather than a rendering question.
